# 🔬 Changing the research harness

[research/README.md](../../research/README.md) explains the case format, the adapter contract, and how to add a tool; this covers the traps.

## 🧱 Results must stay reproducible

- **Byte-identical reruns are the contract.** A change that makes two runs differ — a timestamp, an unsorted key, a column order that depends on which container finished first — is a bug.
- **Never edit `research/results/` by hand**, and never quote a table into a decision record without regenerating it first.
- **Results must match every pin.** Every column records its service's image with its digest and an `inputs` fingerprint of its Dockerfile and lockfiles, and `pnpm research --check-inputs` (run by `research-check.yml`) fails when either moves without its results.
  - A Renovate bump is regenerated by hand on its branch, with the `--profile` command the check prints; [research/README.md](../../research/README.md#️-dependency-bumps) has the steps.
  - **A service that installs from a lockfile or manifest lists it in its `dev.safe-fns.research.inputs` label**, or a bump to it passes unseen. Leave adapter source and cases out; they show up as result diffs.
  - The check reuses the runner's own `toReportedImage` (`scripts/research/images.ts`) and `toServiceInputs` (`scripts/research/inputs.ts`), so change how a column's pins are computed there, never in a copy.
- **Report what the tool actually did.** If a probe needs a wrapper (a parser that returns `{ error }` instead of throwing), keep the call text honest about it.

## 🐳 Containers

- **Pin every image by version and digest**, and pick a tag last pushed at least 7 days ago; Docker Hub's `tag_last_pushed` is the date that counts, since tags get re-pushed.
- **Never pin a pre-release** (`rc3`, `-beta`, `-preview`), even when a bot proposes one; Dependabot's pre-release filter once let Python's through.
  - `.github/renovate.json5` allows `python` only a final `X.Y.Z-` tag, which holds Python's alphas, betas, and release candidates with no range to add per minor.
  - `scripts/research/image-pins.test.ts` fails on any pre-release `image:` or `FROM`, and on a Python hold that lets one through, so a miss shows up in CI.
- **One Compose project per session.** Set `COMPOSE_PROJECT_NAME` (`safe-fns-research-gh-<issue>`) before any `docker compose` or `pnpm research` command, since parallel sessions share one Docker engine and the `db` profile runs `compose up` and a service-scoped `compose down`.
- **After your PR merges, remove only your own project's images**, with the two commands in [research/README.md → Running it](../../research/README.md#-running-it). They match the label Compose stamps on what it builds, never a name prefix, and fail on an unset project name instead of matching every project.
- **Never run a project-wide `docker compose down`, an unscoped `docker image prune`, `docker system prune`, or `docker builder prune`** while another session may be running. The pulled base images and the build cache are kept on purpose; pruning them is the owner's housekeeping.
  - The runner's own `compose down <databases>` is fine: given service names, it removes only those containers and their networks.
- **Track each image's latest stable major.** A new major is a result to record, not a break to avoid; merge it once its results are regenerated.
  - Renovate holds an image from `mcr.microsoft.com` or `ghcr.io` (the .NET SDK, SQL Server, ruff) as pending, since those registries report no push date; check the tag's date and tick it on the Dependency Dashboard once it's 7 days old.
- **An image that several services share moves in one PR**, so its results are regenerated together: Node, 3.x Python, and the .NET SDK today. Renovate's `research` group covers everything under `research/`, so this holds by default.
  - Pin it in one place where you can: `sources` builds from `docker/node/Dockerfile`, and `python` and `sqlite` from `docker/python/Dockerfile`, rather than repeating the pin in `compose.yaml`.
  - `image-pins.test.ts` fails if any other group rule can reach `research/`, which could split a shared image across PRs.
- **Give an image its own Dockerfile when it must be held apart.** A Renovate rule scopes a hold by file, so `python311` is built from `docker/python311/Dockerfile`, which a `matchFileNames` rule holds on 3.11 without holding the other `python` pins.
- **No host ports**, no named volumes, and read-only repo mounts for adapters; only a formatter service mounts `research/adapters` writable.
- **Set the locale explicitly** (`LANG` / `LC_ALL` = `C.UTF-8`); a function that depends on locale gets explicit extra-locale cases rather than the host's.
- **A compiled adapter is built into its image, not mounted** (`c`, `dotnet`, `go`, `jvm`, `rust`, `swift`): the runner's `docker compose build` recompiles it, and its image is the one stage that runs, since the runner reports a Dockerfile's first `FROM` as the column's image.
  - Copy the dependency manifests and restore first, then the sources, so an edit rebuilds only the compile layer; the run then needs no network.
  - Go sets `GOTOOLCHAIN=local`, or it tries to download the toolchain `go.mod` names; .NET uses only the BCL; Rust builds `--locked --offline` against crates fetched in the layer before.
  - A formatter or linter on the same image mounts the source writable over the copy, at the same path, so the image's build caches still apply.
- **The JVM maps `C.UTF-8` to the locale `en`**, which is what its columns report; don't pin `-Duser.country` to match Node's `en-US`.
- **.NET's culture needs ICU and an explicit choice.** `C.UTF-8` maps to the invariant culture, so the adapter sets `InvariantCulture` itself and names each extra culture in its own column.
- **Cargo has no release-age floor.** Pick each locked crate by its crates.io publish date and pin a too-new one back with `cargo update -p <crate> --precise <version>`; Renovate's `minimumReleaseAge` covers later bumps.
- **A formatter must exit non-zero on drift.** `gofmt -l` lists unformatted files but exits 0, so its service wraps it in `sh -c` and fails on any output; `cargo clippy --fix` likewise passes with a denied lint left, so a fixing run then checks.
- **A database is started and removed by the runner**, network and all, not by `depends_on`: adapters run with `--no-deps`. Give it a `database` role label, a healthcheck that only passes once the real server is up (the Postgres and MySQL entrypoints run a socket-only setup server first, so probe over TCP), and an `internal` network shared only with its adapter.
- **SQL Server can't run on `tmpfs`**, and Microsoft publishes it for amd64 only; it runs under emulation on Apple Silicon.
- **Set a service's `platform` in Compose, never on `FROM`.** The runner reads a built image's name from the Dockerfile's first `FROM`, so `FROM --platform=…` would be recorded as the image.
- **Report the version a binary prints, not the one its download claims.** The Hermes v0.13.0 CLI tarball reports 0.12.0.
- **Watch for distro-patched tools.** Python 3.11's image injects setuptools' `distutils` unless `SETUPTOOLS_USE_DISTUTILS=stdlib`; Debian's SQLite is older than upstream. The version column must name what really ran.
  - A tool from a Debian package reports its package version (`5.2.37-2+b10`), which names any Debian patch.
- **Install Debian packages from the base image's snapshot**, as `docker/debian/Dockerfile` does, so a rebuild can't pick up a newer package than the results were made with.
- **Pin every gem, PSGallery module, and other build-time download exactly**, at least 7 days old; a lockfile's transitive versions count too, so check each one's release date.
- **Pin each pnpm root's install scripts.** pnpm refuses an unapproved build script; `research/docker/firebase/pnpm-workspace.yaml` denies the two `firebase-tools` pulls in through `allowBuilds`.

## 🔷 Code

- `scripts/research/*.ts` follows the `scripts/` conventions; the Node adapters (`research/adapters/*.mts` and `node/*.mts`) follow the TypeScript ones and are checked through `research/tsconfig.json`.
- **Choose a new tool's tier by the [Tiers table](../../research/README.md#-tiers)**, not by judgment: tier 2 is set by language (Guava is 2, Ruby's standard library is 4), and tiers 0–2 are what decision records quote, so a wrong tier puts a column in or out of the summary.
- **One module per Node tool.** A library joins as `research/adapters/node/<tool>.mts`, exporting its `Tool`, and is listed in `node.mts`; don't grow the entry file.
- **AssemblyScript's probes typecheck against its own standard library**, through `research/adapters/assemblyscript/tsconfig.json`, which `research/tsconfig.json` excludes.
  - With `noLib`, `number` and `boolean` have no members in its editor typings, so `primitive-methods.d.ts` declares the `toString` that `asc` provides; `asc` never reads it.

  - Prefer a type's own `parse` (`i32.parse`, `f32.parse`, `bool.parse`) over `I32.parseInt` and `Number.parseFloat`, which AssemblyScript deprecates; the globals `parseInt` and `parseFloat` aren't deprecated, and mirror JavaScript's.

  - Its probes compile with `--bindings raw`, which exports `instantiate` rather than one instance, so the driver can replace an instance an abort has poisoned; `--bindings esm` instantiates once, at import. Its calls run one at a time, so none can pick up an instance another just broke.

  - Report what crossed the bindings as it arrived: an `i64` comes back as a bigint and an `f32` as its widened `number`; never convert either to look like JavaScript's answer.

  - Convert with the function form (`i64(value)`), never an assertion (`<i64>value`): the editor typings alias every numeric type to `number`, so `pnpm check`'s lint fix deletes the assertion as unnecessary, and `asc` then rejects the implicit `f64` to `i64` conversion.

- **Hermes runs the TS encoder's own source.** `ENCODER_SOURCE` (in `codec.ts`) and `errorName` (in `node/tool.mts`) are embedded as text in the program Hermes runs, so keep them free of imports and module-level names, and of syntax Hermes lacks, such as classes.
- **The codecs are twins.** A change to `scripts/research/codec.ts` needs the same change in every adapter's codec under `research/adapters/`: `research_codec.py`, `research_codec.php`, `research_codec.psm1`, `research_codec.rb`, `research_codec.swift`, `dotnet/Codec.cs`, `go/codec.go`, `jvm/src/main/java/com/safefns/research/ResearchCodec.java`, and `rust/src/codec.rs`. A `codec.json` case proves it. Hermes needs no twin: it runs `ENCODER_SOURCE`, the encoder's own source.
- **A driven adapter hands the tool a string, never a script.** Pass the value as a positional parameter or environment variable, so no quoting can change what runs; NUL can't travel that way, so it's `n/a`.
- **Check what a CLI probe really evaluated.** systemd strips leading whitespace and treats an empty assignment as a reset, so a blank value never reaches `parse_boolean`; such an input is `n/a`, not a guess.
- **PowerShell unrolls arrays on the pipeline.** Return one with the unary comma (`return , $array`); `Write-Output -NoEnumerate` hands a captured caller a `List` instead.
- **A database adapter reports the server's own version, collation, and error codes**, never the driver's: version and collation by a query (PostgreSQL 16 dropped the `lc_ctype` setting; read `pg_database.datctype`), and an error by its SQLSTATE (`22P02`), MySQL error number (`Error 1292`), SQL Server message number (`Msg 245`), or MongoDB `codeName` (`ConversionFailure`), through `select`'s `error_name`.
- **Non-TS adapters follow the same conventions** ([AGENTS.md → Every language](../../AGENTS.md#-every-language)): Python is fully annotated and documented, keyword-only past one parameter, and checked by `ruff-check`; Java declares every parameter and local it never reassigns `final`, checked by the `checkstyle` service; C# makes every field it never reassigns `readonly`, checked by `dotnet-build`; Rust's `clippy` rejects a needless `mut`; Swift compiles with `-warnings-as-errors`, so a `var` never mutated fails the build. C++ (`const`), Ruby (`frozen_string_literal`, frozen constants), PHP (`readonly` properties), and PowerShell are kept immutable by hand, since their formatters only format.
- **Parse JSON only through `scripts/research/json.ts`** (`parseJson`, `readJsonFile`), whose errors name the file or process; ESLint's `no-restricted-properties` rejects a bare `JSON.parse` in research code. `JSON.stringify` needs no wrapper: it only ever sees encoded values, which hold nothing it throws on.
- **In the JVM adapter, Groovy compiles last**, so only Groovy sees every language's classes: `Main.groovy` is the entry point, and `build.gradle.kts` adds Kotlin's output to `compileGroovy`'s classpath.
- **Name every parameter object type and document every property**, with an `@example`, as AGENTS.md asks of all code.
- **Wrap an `any`-returning library call** in a small function typed `unknown` (`parseJson`, `parseYaml11`) rather than disabling the unsafe-return rule.
