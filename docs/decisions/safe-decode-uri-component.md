# How safeDecodeUriComponent and safeEncodeUriComponent behave

Both are `decodeURIComponent` and `encodeURIComponent` that can't throw: the native result on success, and the caller's fallback, or a replacement they choose, otherwise.

## Decision

- **Signatures:**

  ```ts
  safeDecodeUriComponent(value: unknown, options?: { fallback?: F; usePlusForSpace?: boolean; replaceInvalidWith?: string }): string | F
  safeEncodeUriComponent(value: unknown, options?: { fallback?: F; usePlusForSpace?: boolean; replaceInvalidWith?: string }): string | F
  ```

- **Names** follow [When a name starts with `safe`](safe-prefix-naming.md): `safe` + the native function, with `Uri` cased like `Url`.
- **Accepted input is what TypeScript's own declarations allow:**
  - `safeDecodeUriComponent` takes a string, as `decodeURIComponent(encodedURIComponent: string)` does;
  - `safeEncodeUriComponent` takes a string, a number, or a boolean, as `encodeURIComponent(uriComponent: string | number | boolean)` does, converted as the native call converts it (`42` → `"42"`, `true` → `"true"`);
  - a boxed string, number, or boolean is unwrapped by brand check first;
  - anything else returns the fallback, where the native call would coerce it: `decodeURIComponent(null)` is `"null"`, and `encodeURIComponent(["a b"])` is `"a%20b"`.
- **A string gets exactly the native result,** with nothing trimmed or rewritten:
  - `" a%20b "` decodes to `" a b "`, and `""` to `""`; this is a native wrapper, not a parser, so blank text isn't the fallback;
  - `+` stays a literal plus by default (`"a+b"` → `"a+b"`), as the native calls keep it;
  - `%2F`, `%3F`, and the other reserved characters decode (`"a%2Fb"` → `"a/b"`), and encoding escapes them.
- **`safeDecodeUriComponent` returns the fallback wherever `decodeURIComponent` throws `URIError`:**
  - a malformed escape: `"%"`, `"100%"`, `"%2"`, `"%zz"`;
  - escapes that aren't UTF-8: a stray byte (`"%FF"`), a truncated sequence (`"%C3"`), an overlong form (`"%C0%AF"`), an encoded surrogate (`"%ED%A0%80"`), and a code point past U+10FFFF (`"%F4%90%80%80"`).
- **`safeEncodeUriComponent` returns the fallback wherever `encodeURIComponent` throws `URIError`:** a lone surrogate anywhere in the string, which slicing a string through an emoji (`"a😀".slice(0, 2)`) produces.
- **`replaceInvalidWith` converts what can't be converted instead of failing.** Unset, the whole call returns the fallback; set, the call always returns a string for accepted input.
  - Decoding, a `%` that doesn't start a two-hex-digit escape is replaced, and the text after it is kept: `"100%"` → `"100�"`, `"%zz"` → `"�zz"`.
  - Decoding, each escaped byte sequence that isn't UTF-8 is replaced once per maximal invalid subpart, as `TextDecoder` counts them: `"%FF"` → `"�"`, `"%C0%AF"` → `"��"`.
  - Encoding, each lone surrogate is replaced before escaping, as `String.prototype.toWellFormed` does with U+FFFD: `"a\uD83D"` → `"a%EF%BF%BD"` with `replaceInvalidWith: "\uFFFD"`.
  - `"\uFFFD"` is the conventional replacement character, and `""` drops what can't be converted; the replacement itself is inserted as-is when decoding and escaped when encoding.
  - It never decodes part of a string and keeps the rest unchanged, as the `decode-uri-component` package does, since that leaves a caller unable to tell decoded text from undecoded.
- **`usePlusForSpace: true` switches both functions to the form encoding `URLSearchParams` uses for spaces:**
  - decoding turns `+` into a space before unescaping, so `"a+b"` → `"a b"` while `"%2B"` is still `"+"`, as Java's `URLDecoder` and Go's `QueryUnescape` do;
  - encoding writes a space as `+` instead of `%20`, so `"a b"` → `"a+b"`, while a literal `+` is still escaped as `%2B`, as Java's `URLEncoder` and Go's `QueryEscape` do;
  - nothing else about form encoding changes: the same characters are escaped as without it.
- **`decodeURI` and `encodeURI` get no wrapper.** They skip the reserved characters (`decodeURI("a%2Fb")` stays `"a%2Fb"`), so they suit only a whole URI, and a whole URI belongs to [`safeParseUrl`](safe-parse-url.md).

## Why

- `decodeURIComponent` throws on text a user can type: a literal `%` (`"100%"`) or a truncated link is enough, so every call on untrusted input needs a `try`.
- Strict beats lenient for a function whose callers can't see what happened:
  - JavaScript, Hermes, Go, Java, and Spring all throw on a malformed escape (`"%"`, `"%zz"`); only Python and .NET keep it as text;
  - the lenient tools disagree with each other: on `"%FF"`, `decode-uri-component` keeps `"%FF"`, Node's `querystring.unescape` and Python's `unquote` return `"�"`, and .NET's `Uri.UnescapeDataString` keeps the escape;
  - `fast-decode-uri-component`, used by Fastify, returns `null` on every malformed case, which is the same rule with a fixed fallback.
- The accepted types follow TypeScript's declarations, the line every TypeScript caller already writes to:
  - the native calls coerce anything through `ToString`, the rule every ECMAScript global string function has followed since the first edition, not a choice made for URIs, so `null` becomes the real text `"null"`;
  - encoding a number is common and intended: GitHub code search, on 2026-10-21, found `encodeURIComponent(id)` in about 234,000 TypeScript and JavaScript files, and `encodeURIComponent(String(` in about 141,000, written where the number is converted by hand;
  - decoding one is rare, since encoded text arrives as text: `decodeURIComponent(String(` appears in about 15,000.
- `replaceInvalidWith` mirrors two platform conventions rather than inventing one: `TextDecoder`'s U+FFFD for bytes that aren't UTF-8, and `toWellFormed`'s U+FFFD for lone surrogates; a malformed `%` is replaced too, so no undecoded escape syntax survives into the result.
- The option is named for what it does at the call site, `{ replaceInvalidWith: "\uFFFD" }`, as Java's `CharsetDecoder.replaceWith` is; `replacement` alone wouldn't say what gets replaced, beside a `fallback` that replaces the whole result.
- `usePlusForSpace` is a verb phrase like the package's other boolean options (`clamp`, `ignoreCase`, `sortArrays`), and reads the same in both directions: decoding takes `+` to stand for a space, and encoding writes `+` for one.
- `usePlusForSpace` covers the one difference between a URI component and form data that callers trip on; the rest of form encoding already lives in `URLSearchParams`.
- GitHub code search, on 2026-10-21, found `safeDecodeURIComponent` in 7,712 files and `tryDecodeURIComponent` in 4,512, against 748 for `safeEncodeURIComponent` (approximate, every language, case-insensitive).
  - Decoding is where the wrapper gets written, about ten to one, but encoding fails too, and a total pair costs little more than one.

## Consequences

- A caller decoding a whole query string still uses `URLSearchParams`, which already never throws; `usePlusForSpace` is for one form value on its own.
- `safeDecodeUriComponent(text, { fallback: text })` keeps undecodable text exactly as it was, and `{ replaceInvalidWith: "\uFFFD" }` decodes everything it can.
