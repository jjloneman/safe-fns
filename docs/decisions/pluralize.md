# How pluralize picks a form

`pluralize(word, count)` returns `word` or its English plural, chosen by `count`: `pluralize("box", 2)` is `"boxes"`.

## Decision

- **The word comes first, then the count:** `pluralize(word, count, options)`, the order of the pluralize and plur packages.
  - Both are values the function works on, so both are positional, per [How a function takes its parameters](function-parameters.md).
- **The singular is returned exactly when the count is `1` or `-1`,** as English's plural rule in `Intl.PluralRules("en")` and plur have it.
  - Every other number takes the plural: `0`, `2`, `-2`, `0.5`, `1.5`, `-0`, `NaN`, and `±Infinity`.
  - A bigint counts the same way (`1n` is singular).
  - A boxed `Number` or `BigInt` is unwrapped first, by a brand check on the object path only, so the common call is still one `typeof`.
  - Anything else, numeric strings included, takes the plural, so a bad count never loses the word; the count is never parsed, which would widen the check (owner, 2026-10-28).
- **The plural is the `plural` option when given,** used as written: `pluralize("child", 2, { plural: "children" })` is `"children"`.
- **Otherwise a built-in English suffix, with no dictionary:**
  - `-s`, `-x`, `-z`, `-ch`, and `-sh` take `-es` (`"boxes"`, `"buses"`, `"churches"`);
  - a consonant followed by a lowercase `y` becomes `-ies` (`"cities"`), and a vowel followed by `-y` takes `-s` (`"days"`);
  - everything else takes `-s`, including `-o` (`"photos"`) and `-f` (`"leafs"`);
  - irregular words need the `plural` option: `"childs"`, `"quizes"`, `"potatos"`, and `"sheeps"` are what the rules alone give;
  - the suffix follows a word's last character, so `"status code"` becomes `"status codes"`.
- **The suffix is always lowercase,** whatever the word's case: `"API"` → `"APIs"`, `"ID"` → `"IDs"`, `"OS"` → `"OSes"`, and `"AoB"` → `"AoBs"`.
  - An all-caps word keeps its `Y`, so `"CITY"` → `"CITYs"`, and `"BOX"` → `"BOXes"`.
  - A caller who wants shouting writes `pluralize(word, count).toUpperCase()`.
- **`includeCount: true` prefixes the count and a space,** written by `String(count)`: `"3 boxes"`, `"1 box"`.
- **An empty word stays empty.**
- **A non-string word returns the `fallback` option, `""` by default,** as [trimBlank](trim-blank.md) does.
- **English only.** There is no locale option, and the package never calls `Intl.PluralRules`.

## Why

- **No dictionary keeps the package small and predictable.** pluralize and Rails ship inflection dictionaries (`"cacti"`, `"analyses"`, `"mice"`), and disagree with each other (`"cactus"` is `"cacti"` in pluralize and `"cactus"` in Rails); a caller who names the plural gets exactly what they wrote.
- **`-1` is singular** in English usage and in Spanish, and in the standard plural rules (owner, 2026-10-28):
  - English grammar references define the singular as "one (or minus one)", with every other amount plural ("zero degrees", "0.5 children", "minus five degrees"), and "minus one degree" is the common phrasing;
  - the RAE gives the singular only to the exact unit ("1 grado"), with zero and decimals plural ("0 grados", "0,5 metros"), and Wikilengua writes "−1 grado Celsius";
  - CLDR's English rule tests the number's absolute value, which `Intl.PluralRules("en")` and plur follow;
  - no major style guide (AP, Chicago, APA) or Stack Exchange answer rules on `-1` directly, as of 2026-10-28;
  - pluralize and Rails test `count === 1`, so `-1` takes their plural.
- **No `Intl.PluralRules`:** whether an engine has `Intl` depends on how it was built; the Hermes CLI measured has none, so every case throws a `ReferenceError`. A function that called it would answer differently from engine to engine, which [What every export promises](package-promise.md) rules out.
- **`String(count)` for the count,** not `toLocaleString`, for the same reason: `"1000 boxes"` is the same everywhere, and a caller who wants `"1,000 boxes"` formats the count and leaves `includeCount` off.
- **Word first** keeps the order of the libraries JavaScript code already calls (owner, 2026-10-28); Rails' view helper and Ember take the count first.
- **A lowercase suffix** is how APA (7th ed.) forms an abbreviation's plural ("URLs", "CDs"), and most all-caps words in an interface are abbreviations; Rails agrees (`"APIs"`, `"BOXes"`), while pluralize and plur uppercase it (`"APIS"`).

## Consequences

- The README lists the suffix rules and shows the `plural` option for irregular words.
- A word whose plural the rules get wrong is a caller's `plural` option, never a new rule, unless the rule is wrong for a whole class of words.
