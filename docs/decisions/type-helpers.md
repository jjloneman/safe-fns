# What PartialDeep and EnumLiteralsDeep do

`PartialDeep<Config>` types a partial override of a nested config, and `EnumLiteralsDeep<Payload>` lets `{ day: "Monday" }` type-check where a field is a string enum. They replace the owner's two copies of `PartialDeep`, which walked into functions and `Date`s, skipped `Address | null`, and named the DOM's `Node`, and spare a project from installing type-fest for one type.

## Decision

- **Signatures:**

  ```ts
  type PartialDeep<T, Leaf = never> = …;
  type EnumLiteralsDeep<T, Leaf = never> = …;
  ```

  - `T` is the type to convert; `Leaf` is a caller's "stop here" type, kept whole, such as `Node` for a DOM project or a domain type with its own invariants (`PartialDeep<Form, File | Node>`).
  - `Leaf` replaces the owner's DOM-safe variant, whose hard-coded `Node` fails with `Cannot find name 'Node'` in a project without the DOM `lib`; the helpers name no global that `lib: ["es2022"]` lacks.
  - The names are the owner's; `PartialDeep` matches type-fest's, and both put `Deep` last, as `EnumLiteralsDeep` reads.
  - The TSDoc uses `@typeParam`, not JSDoc's `@template`.

- **Each is its own subpath:** `safe-fns/partial-deep` and `safe-fns/enum-literals-deep`, one export per file as every function has, imported with `import type`.
  - What they share, the leaf and primitive unions, lives in a non-public module under `src/internal/`, per [How exports share code](internal-dependencies.md).
  - A types-only entry builds to an empty module: `test:consumer`'s smoke check loads it and finds no runtime names on either side, the root re-exports it with `export type`, and `size-limit.config.ts` gives it a budget like any entry.
- **Both distribute over unions,** so `Address | null` becomes a partial `Address` or `null`; the owner's version checked `T[K]` as a whole and left `Address` untouched.
- **Kept whole, never walked into:**
  - `any` and `unknown`, which stay themselves instead of becoming `{}` or a union of both branches;
  - primitives, including `string` and string literals;
  - functions and constructors, so a function field still takes only a function, not any object;
  - `Date`, `Error`, `RegExp`, `Promise`, `Map`, `Set`, their read-only and weak forms, `ArrayBuffer`, and typed arrays, whose fields are internal state, not data;
  - the caller's `Leaf` types.
- **Arrays and tuples are mapped item by item** with a homomorphic mapped type, so an array stays an array, mutable or `readonly` as it was, and a tuple keeps its length.
  - `PartialDeep` makes each item partial but never makes an item optional: `Address[]` becomes `PartialAddress[]`, not `(PartialAddress | undefined)[]`.
  - The owner's DOM-safe variant turned mutable arrays `readonly` and tuples into plain arrays.
- **Objects:** `PartialDeep` makes every property optional; `EnumLiteralsDeep` keeps each property's modifiers. Both keep `readonly`.
- **`EnumLiteralsDeep` converts string enums only:** a string enum `Day` becomes `` `${Day}` ``, the union of its values, while a numeric enum stays the enum, since a number already type-checks against one.
  - The two compose: `PartialDeep<EnumLiteralsDeep<Payload>>` is a partial payload written with literals.
- **They parse on TypeScript 4.9,** the consumer floor, with no `const` type parameters or `NoInfer`, and every check below passes on 4.9.5, 5.0.4, 5.4.5, 5.9.3, 6.0.3, and 7.0.2.
- **The package promise, for a type:** a type can't throw, so "total" means no surprise result — no `never`, no `{}`, and no `any` that the input didn't have — and no "excessively deep" error for an ordinary recursive type, such as a tree whose `children` are trees.

## Comparison

The tables come from [research/audits/partial-deep.md](../../research/audits/partial-deep.md) and [research/audits/enum-literals-deep.md](../../research/audits/enum-literals-deep.md), generated by `pnpm research:types`.

- The harness behind `pnpm research` compares runtime values, so a type is checked by the compiler instead: each cell is one file holding one assertion, compiled by every consumer TypeScript version the package supports.
  - The compilers are the root's `typescript-<version>` aliases, and the libraries are installed in `research/types/`, their own pnpm root, so the two lockfiles pin every input.
  - Each file compiles with `strict`, `lib: ["es2022"]`, no `types`, and `skipLibCheck`.
- ✅ means the assertion compiled on every version; ❌ names the errors, and the versions they came from when not every version failed alike. `TS2344` is the assertion failing; `TS2314` and `TS2559` mean the helper takes no second type argument of that kind.
- Each tool runs with its defaults: type-fest's `PartialDeep` doesn't walk into arrays unless `recurseIntoArrays` is set, which is why its array and recursive-type rows fail.
- No library has an enum-to-literals helper, so `EnumLiteralsDeep` has only its planned column.

## Why

- **Not type-fest:** it fails most rows on 4.9, the package's consumer floor; on newer compilers it still walks into `Map`, `Promise`, and typed arrays, leaves arrays whole by default, and fails the `readonly`-array and tuple rows; a project would install it for one type.
- **Not ts-essentials:** the closest on objects, but it walks into `Map`, `Promise`, and typed arrays, and fails every array and tuple row.
- **Not utility-types:** it walks into `Date`, `Map`, `Promise`, and typed arrays, changes `any` and `unknown`, and fails the `readonly`-array and tuple rows.
- **No library takes a stop type,** which is what lets a DOM project keep `Node` whole without the helper naming `Node`.
- **Items are never made optional:** a partial list of addresses is still a list of addresses; an `undefined` hole is a different type, which type-fest offers behind an option.

## Consequences

- The ✨ API issue adds the two subpaths, the internal leaf module, the root's `export type` re-exports, a `size-limit` budget for each empty entry, and `test/consumer/types.ts` imports for both.
- Their type tests (`*.test-d.ts`) cover every row above, so a regression fails `pnpm test`; `pnpm research:types` stays the cross-version check against the consumer compilers.
- The docs show a nested config override with `PartialDeep`, a JSON payload typed with `EnumLiteralsDeep`, and `Leaf` keeping `Node` whole.
