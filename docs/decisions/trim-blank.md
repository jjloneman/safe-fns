# What trimBlank trims

`trimBlank(value)` removes blank characters from both ends of a string, where "blank" means exactly what [`isSafeEmpty`](is-safe-empty.md) calls blank; `trimBlankStart` and `trimBlankEnd` remove them from one end.

## Decision

- **The blank set is `isSafeEmpty`'s,** from the one shared module the parsers already use:
  - `\p{White_Space}`, which adds NEL (`\u0085`) to what `String.prototype.trim` strips;
  - `\p{Default_Ignorable_Code_Point}`: the zero-width space, word joiner, soft hyphen, BOM, Hangul fillers, variation selectors, and tag characters;
  - the braille blank, `\u2800`.
- **Characters between non-blank text are kept:** `"a \u200B b"` comes back unchanged.
- **A grapheme cluster is never split.**
  - A blank `Grapheme_Extend` character directly after the last non-blank character belongs to it, so it stays: `"❤\uFE0F"` keeps its emoji variation selector, and a subdivision flag such as 🏴󠁧󠁢󠁥󠁮󠁧󠁿 keeps its tag characters.
  - Anything blank after that run is trimmed: `"❤\uFE0F\u200B"` → `"❤\uFE0F"`.
  - A trailing zero-width joiner is trimmed, `"a\u200D"` → `"a"`, since it isn't `Grapheme_Extend` and joins nothing.
  - At the start there is no character to attach to, so a leading variation selector is trimmed like any other blank.
- **The result is `""` exactly when `isSafeEmpty` calls the input blank.**
- **`trimBlankStart` and `trimBlankEnd` ship too,** named after `trimStart` and `trimEnd`.
- **A non-string returns the `fallback` option, `""` by default:** `trimBlank(value, { fallback })`.
  - The input is typed `string`, so the return is `string` unless a fallback of another type is passed: `{ fallback: undefined }` gives `string | undefined`.
  - A boxed string is unwrapped first, identified by a brand check, as every parser does.
  - The fallback covers only non-string input; a blank string still trims to `""`, where `safeParseString` would return its fallback.
- **A lone surrogate isn't blank,** so it's kept wherever it sits.

## Why

- **No tool measured trims an invisible character.** Every column keeps the zero-width space, word joiner, soft hyphen, Hangul fillers, and braille blank at both ends.
  - Only the JavaScript built-ins, Hermes, lodash, and es-toolkit trim the BOM.
  - Only .NET, Go, Guava, Python, and Rust trim NEL.
  - So a pasted `"\u200Bhi"` stays `"\u200Bhi"` everywhere else, which is the gap `trimBlank` fills.
- **One blank set and one trim for the whole package** means `trimBlank(s) === ""` and `isSafeEmpty(s)` never disagree, and every parser trims exactly what `trimBlank` does.
- **Keeping the grapheme intact fails safe toward preserving data.** The default-ignorable set includes the variation selectors and tag characters, so a plain character-class trim would turn `"❤\uFE0F"` into the text-style `"❤"` and break a flag into a black flag plus invisible tags.
  - `Grapheme_Extend` is a standard ECMAScript property escape (`\p{Grapheme_Extend}`), so the rule needs no `Intl.Segmenter` and gives the same result in every engine.
- **A `fallback` option** matches how every parser reports input it can't use, and its `""` default keeps the common call typed `string`.
  - lodash stringifies instead (`_.trim(42)` is `"42"`), which turns objects into `"[object Object]"` and runs `toString` traps, and es-toolkit's `trim` throws a `TypeError`.
- **Start and end variants** cost little, and mirror the native trio, so a caller replacing `trimEnd` doesn't have to trim both ends.

## Consequences

- `trimBlank` moves from a planned internal helper to a public export, and the shared blank module under `src/internal/` exports it to both.
- The parser records ([safeParseNumber](safe-parse-number.md), [safeParseBigInt](safe-parse-big-int.md), [safeParseBoolean](safe-parse-boolean.md), [safeParseString](safe-parse-string.md), [safeParseDate](safe-parse-date.md), [safeParseUrl](safe-parse-url.md)) and [is-safe-empty.md](is-safe-empty.md) call it "the internal `trimBlank`"; #100 rewords them.
- The grapheme rule reaches the parsers too, and was chosen for them as well (owner, 2026-10-28): `safeParseNumber("42\uFE0F")` keeps the variation selector and returns the fallback rather than guessing `42`, as [What a parser returns when it can't parse](parser-fallbacks.md) asks, and `safeParseString("❤\uFE0F")` keeps the emoji.
  - The parser records say they strip blank characters "from both ends"; #100 adds that a modifier attached to the last character stays.
- Property escapes follow each engine's Unicode version; the tests pin the characters above, not the whole table.
